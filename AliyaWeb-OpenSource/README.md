# AliyaWeb · V1.1

> **⚠️ 这是非官方的粉丝二次创作（同人改写）作品。**  
> 基于 瞳电游工作室 的游戏 **《彼方的她 - Aliya》(Aliya: Timelink)** 改写而成，  
> 与原作者及开发方**没有任何隶属关系**，也不代表其立场。

仿照游戏《彼方的她》制作的 AI 网页聊天机器人 —— **二创改写版**。  
目前包含 **DeepSeek 驱动的 Aliya 对话**、**游戏原声循环播放**（可开关 / 调音量），  
以及可查看与导出**完整记忆档案**的上下文面板。

## 运行方式

### Windows 一键启动（不想折腾 Node 就用这个）

到 [Releases](../../releases) 下载 `AliyaWeb-Launcher.exe`（约 20 KB），放到项目根目录（与 `Web/`、`README.md` 同级），双击运行。它会按顺序自动做完：

1. **找 Node.js** —— 系统里没装就下载便携版（约 36 MB，只放在项目内的 `.node-runtime/`，不写注册表、不要管理员权限）
2. **装依赖** —— `npm install`，只装 express / axios / dotenv / cors 这几个生产依赖
3. **配密钥** —— 提示你粘贴 DeepSeek API Key（输入不回显），写进 `Web/.env`；已经填过就不覆盖
4. **起服务并开页面** —— 探测到 `http://localhost:5000/api/test` 通了，才用默认浏览器打开首页
5. **停止** —— 关掉那个黑色命令行窗口，Node 进程跟着一起退出

几件必须知道的：

- 第一次运行需要联网（下载 Node 与依赖）。失败时窗口里保留 npm / 下载的原始报错，可对照下面的手动方式排查。
- exe **没有代码签名**，Windows 会拦一次「SmartScreen 已阻止」→ 点「**更多信息**」→「**仍要运行**」。
- 不信任 exe 的话可以本地自己编译：源码 [`tools/AliyaWebLauncher.cs`](./tools/AliyaWebLauncher.cs)，
  用 Windows 自带的 `csc.exe` 就够（**不需要** Visual Studio 或 dotnet SDK），双击 [`tools/build.cmd`](./tools/build.cmd)。
- 命令行参数：`--key=sk-xxx`（免交互）、`--port=5000`、`--no-browser`、`--skip-install`、`--no-download`、`--no-pause`。
- 只支持 Windows x64；macOS / Linux 请用下面的手动方式。

### 手动方式（macOS / Linux / 开发者）

```bash
cd Web
npm install

# 复制环境变量模板并填写
copy .env.example .env      # macOS / Linux: cp .env.example .env
# 编辑 .env，把 DEEPSEEK_API_KEY 换成你自己的密钥（必填）
# 申请地址：https://platform.deepseek.com/api_keys

npm start
```

然后浏览器打开 <http://localhost:5000>（端口可在 `.env` 中修改）。

- 未配置 `DEEPSEEK_API_KEY` 时，服务依然会启动、页面也能打开，  
  但发送消息会收到明确的“未配置”提示，而不是一个没有头绪的 500。
- 开发模式（改动自动重启）：`npm run dev`

## 实现要点

### 对话

- **人设**：`server.js` 中的 `systemPrompt` 定义了 Aliya 的角色、世界观与语言风格  
  （回复用 `/` 分隔短句，前端会拆成多条气泡逐条显示）。
- **记忆压缩**：每累计 10 轮对话，就把这段历史递归压缩成 150 字以内的“长期记忆”，  
  压缩结果会作为一条 system 消息带进后续请求，避免上下文无限增长。
- **会话持久化**：会话表会以防抖方式写入 `data/sessions.json`，  
  写入采用「临时文件 + 原子重命名」，服务重启后自动恢复；  
  按 `Ctrl+C` 退出时会同步落盘。最多保留最近活跃的 200 个会话。

### 上下文面板与「记忆档案」

点导航栏左侧的「上下文」按钮，右侧会滑出一个抽屉（默认收起，`Esc` 或再点一次关闭）：

- **上下文状态**：当前工作窗口轮次 / 估算 Token / 已压缩块数 / 距下次自动压缩还有几轮
- **记忆档案**：记忆总条数、你与 Aliya 各说过多少条、最早一条的时间
- **长期记忆**：后端递归压缩出的那段总结全文（以前只发给模型，前端完全看不到）
- **下载记忆 .md**：让浏览器直接另存为一份完整记忆档案
- **导出到 data/**：把同一份内容写到 `Web/data/aliya-memory-<会话ID>.md`

面板打开时每次对话结束会自动刷新；收起时不发任何请求。

#### 为什么需要「档案」

发给模型的上下文必须收敛，所以累计满 10 轮时会把原文递归压缩成一段总结 ——  
**但这不该意味着聊过的内容被销毁**。因此每条消息都会另外追加一份只读档案：

```
Web/data/transcripts/<会话ID>.jsonl      # 每行一个 {role, content, at}
```

档案**只追加、永不裁剪**，与发给模型的工作窗口完全独立。于是：

- 被压缩掉的那 10 轮原文，导出/下载时**依然一句不少**
- 导出的 markdown 含全部轮次（`### 第 N 轮`）、每条的时间戳，以及那段长期记忆
- 「清空对话」默认**只重置工作窗口、保留档案** —— 免得一下手滑毁掉你想留存的东西；  
  真要彻底删除，用 `DELETE /api/session/<会话ID>?purge=1`

> `sessionId` 会参与拼文件名，因此后端对它做了严格校验  
> （只允许字母、数字、下划线、连字符，长度 1–64），  
> 防止用 `../../` 之类的 ID 把文件写到 `data/` 之外。

### 设置面板与游戏原声

导航栏左侧的「设置 ▾」按钮打开一个独立抽屉（与「上下文」互斥，不会同时展开），  
音乐相关的调整都在这里，主界面其余部分不受影响：

- **播放音乐**：总开关
- **音量**：滑块 0–100%，默认 **35%**（作为聊天背景音的合适档位）
- **当前曲目**：显示曲名与 `第 N / 7 首`，可点 ◀ / ▶ 手动切换

曲目取自游戏原声包 **《AliyaSoundtrack》**（Steam 音乐包）中的 `MP3/` 目录，  
已复制到 `public/system/music/soundtrack/` 并改成 URL 友好的文件名：

| # | 曲目                  | 时长   | 文件                          |
| - | ------------------- | ---- | --------------------------- |
| 1 | Aliya               | 0:22 | `01-aliya.mp3`              |
| 2 | Drift               | 2:16 | `02-drift.mp3`              |
| 3 | Response            | 2:46 | `03-response.mp3`           |
| 4 | Letter              | 1:38 | `04-letter.mp3`             |
| 5 | Astral Sunset       | 1:42 | `05-astral-sunset.mp3`      |
| 6 | Stars' Annihilation | 2:19 | `06-stars-annihilation.mp3` |
| 7 | Tranquil Repose     | 3:42 | `07-tranquil-repose.mp3`    |

共 33.7 MB，按顺序**循环播放**。实现要点：

- 全程只有**一个 `<audio>`**，`preload='none'`，播完一首（`ended`）才换 `src` 加载下一首 ——  
  任何时刻只下载当前这一首，不会一次性拉 33.7 MB。
- 开关与音量存在 `localStorage`（键 `aliya.music`），刷新后保留。
- 实际音量 = 开关 × 音量滑块。

> 原音乐包里另有 `WAV/`（同样 7 首的无损版，255 MB）与 `CG/`「Cartoon/」等立绘素材，  
> 都与播放无关，**没有打包进来**。

### 右下角等待动画

右下角 `PlayerChoice.png` 屏幕里的三根条是一个 **35 帧动画**  
（`system/wait/dian_0.png` ~ `dian_34.png`）：三根条依次向上弹起约 20px，  
错开成一道波浪，循环播放。

`wait.js` 会**先把 35 帧全部预加载进缓存再开始播放** —— 原实现每 24ms 直接换 `<img src>`，  
首轮还没进缓存会逐帧发起请求，导致明显的闪烁。另外还有两个稳健性处理：  
3 秒兜底启动（个别帧加载失败也不会让动画永久停摆）与切到后台自动暂停。

## 已知问题 / 可继续优化的点

- 收音机调频退役后留下的 3 个无引用素材  
  （`RadioNoise.ogg` 11MB、`RadioPin.png` 14KB、`背景.ogg` 13.5MB，合计约 **24.5MB**）  
  **已从仓库移除** —— 体积从约 60MB 降到约 **36MB**。
- 目前占比最大的仍是游戏原声 7 首（33.7 MB）。若在意体积，  
  可用 ffmpeg 转成 128kbps 的 ogg，预计能压到 7MB 左右（音质损失在背景音场景基本听不出）。
- `public/system/wait/PlayerChoice.png` 是 1743×994、1.5MB，  
  而实际显示高度最多只有视口的 25%（约 200-300px），存在明显的分辨率冗余，  
  可在保留备份的前提下等比缩小。
- **压缩会让「发给模型的」上下文丢掉近因**：累计满 10 轮时，这 10 轮原文会被压缩掉，  
  模型只能看到「人设 + 长期记忆 + 最新一句」，最近几轮的原话不再可见。  
  注意这**只影响发给模型的上下文预算，不影响你的记忆档案**  
  （档案里原文一句不少，导出/下载都能拿到）。  
  若想同时给模型保留近因，可以改成只压缩较早的 8 轮、留最后 2 轮原文  
  （调整 `server.js` 里传给 `splitMessagesByTurns` 的轮数即可）。
- 会话以 JSON 明文存储，未包含任何加密或用户隔离，仅适合本地 / 个人使用。
